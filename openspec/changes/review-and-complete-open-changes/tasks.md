## 1. Inventory Active Changes

- [ ] 1.1 For each active change from `openspec list`, record: total tasks, completed tasks, and domains affected.
- [ ] 1.2 Briefly summarize the intent of each change and whether the codebase appears to have implemented it already.

## 2. Decide Disposition

- [ ] 2.1 Define criteria for:
  - Completing an existing change.
  - Splitting a change into smaller follow-ups.
  - Archiving a change as abandoned/incomplete.
- [ ] 2.2 Apply the criteria to each active change and propose a disposition (complete, split, archive).

## 3. Apply Decisions

- [ ] 3.1 For changes to complete now, ensure their `tasks.md` are up to date and prepared for `openspec-apply`.
- [ ] 3.2 For changes to archive, move them under `openspec/changes/archive/` and add a short `status.md` or note explaining why.

## 4. Governance Documentation

- [ ] 4.1 Update `openspec/project.md` with guidelines on when and how to archive partially completed changes.
- [ ] 4.2 Optionally, add a short summary mapping major capabilities to the archived changes that introduced them.
