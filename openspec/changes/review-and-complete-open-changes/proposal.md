# Change: Review and Normalize Active OpenSpec Changes

## Why

There are multiple active OpenSpec changes with partially completed task lists. Some are nearly complete, others have no tasks done. Without a clear policy, it is hard to know which changes should be finished now, which should be archived as abandoned, and how they relate to the current codebase.

## What Changes

- Systematically review all active OpenSpec changes and determine their status relative to the current implementation.
- Decide for each change whether to complete it, split it, or archive it with a clear rationale.
- Document a process for handling partially completed changes going forward.

## Impact

- Affected specs: `operations` (OpenSpec governance), and indirectly all domains touched by active changes.
- Affected files: `openspec/changes/*` directories, `openspec/project.md`.
- Clarifies the state of the spec system and reduces confusion for future work.
