# Change: Implement LLM Question Generation

## Why

The architecture specifies that question text should be generated by LLM, not hardcoded templates. Currently, `get_semantic_questions.sql` uses `'Does it have ' || clause || '?'` and `get_geographic_questions.sql` uses `'Is it in ' || name || '?'`. This produces robotic, unnatural questions that don't match the documented experience in `docs/architecture/algorithm.md`.

## What Changes

- **Database function**: Modify `get_question()` to call `call-llm` edge function after algorithmic selection
- **Question flow**: Algorithm selects trait/region (deterministic) -> LLM generates natural language question (creative)
- **Remove templates**: Delete hardcoded "Does it have" / "Is it in" string patterns
- **Add HTTP call**: Create `http_call_edge_function()` wrapper for calling edge functions from database

## Impact

- Affected specs: algorithm
- Affected code: `supabase/db/game_logic/functions/questions/`, `supabase/functions/call-llm/`
- Questions become conversational rather than formulaic
