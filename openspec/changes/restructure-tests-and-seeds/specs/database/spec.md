# Database Spec: Restructure Tests and Seeds

## Data Organization

### Schema Data (supabase/db/game_logic/data/)

Files that are part of the migration:

#### config.sql

Contains game configuration values (excludes runtime.\* keys):

- `game.max_turns`
- `llm.*` settings
- `confidence.*` thresholds
- `scoring.*` parameters
- `traits.*` factors
- `questions.*` settings

#### geographic_regions.sql

Contains geographic region polygons generated from Natural Earth data.
Generated by `scripts/generate-geographic-regions.ts`.

### Seed Data (supabase/seeds/)

Files for dev/CI only:

#### 00_dev_runtime.sql

Runtime configuration for local Docker networking:

- `runtime.supabase_url` (host.docker.internal)
- `runtime.supabase_anon_key`
- `runtime.supabase_service_role_key`

#### 01_dev_users.sql

Test users for local development.

#### 02_dev_data.sql

Pre-computed embeddings and test place data for running tests without edge functions.

## Test Organization

### test_game_flow.sql

Tests game lifecycle:

- `start_game()` returns valid session with candidates
- Candidates have normalized probabilities
- Embeddings are created for session descriptions
- Config controls behavior (threshold test)
- `play_turn()` updates game state correctly
- Game ends after max turns or correct guess

### test_places.sql

Tests places domain:

- Places RLS: publicly readable
- `submit_place()` creates place correctly
- Place traits are publicly readable

### test_sessions.sql

Tests sessions domain:

- Sessions RLS: users can only see own sessions
- Users can create sessions for themselves
- Users cannot create sessions for others
- Answers RLS: follows session ownership
- Service role has full access

### test_algorithm.sql

Tests scoring functions (existing file, keep as-is):

- `calculate_prior_scores()`
- `calculate_posterior_scores()`
- `select_best_question()`
- Probability normalization
